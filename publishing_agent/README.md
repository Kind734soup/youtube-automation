# Publishing Agent

Turns a finished project into `upload_manifest.json` - everything a
YouTube upload needs, gathered in one place. It is a completely separate
agent from the Research Agent (`agent/`), Script Agent (`script_agent/`),
Video Production Agent (`video_production_agent/`), Voice Generation
Agent (`voice_generation_agent/`), Video Editor Agent
(`video_editor_agent/`), FFmpeg Render Agent (`ffmpeg_render_agent/`),
and Visual Generation Agent (`visual_generation_agent/`) - it does not
import from any of them, and does not modify anything they produce.

**This agent does not call the YouTube API or upload anything.** For
Version 1 it only writes `upload_manifest.json` and, via `publish`, runs
a free, offline `ManualProvider` that prints a checklist for uploading
by hand. Wiring up a real provider (YouTube Data API) is future work -
see "Adding a publishing provider" below.

## What it consumes

Two folders, matching the convention every other agent in this pipeline
already uses:

- `scripts/<topic-slug>_<date>/`
  - `metadata.json` (required) - `topic` becomes the title/description
    source; `target_minutes` is mentioned in the description
  - `edit_manifest.json` (optional, preferred) - its `timeline` gives
    chapters real, rendered `start_time_seconds`
  - `production_manifest.json` (optional, fallback) - used for chapters
    only if `edit_manifest.json` isn't present; its scene titles and
    `estimated_duration_seconds` are summed instead, and each resulting
    chapter is flagged `"estimated": true`
- `final/<topic-slug>_<date>/` (same folder name, written by the FFmpeg
  Render Agent)
  - `final.mp4` (required)
  - `subtitles.srt` (required) - recorded in the manifest's `source`,
    not parsed for content
  - `thumbnail.png` (optional - future input; not generated by any
    agent yet, so today this is almost always reported missing)

It never reads `script.md`, `scene_descriptions.md`,
`narration_manifest.json`, or any `assets/` folder.

## What it produces

`final/<topic-slug>_<date>/upload_manifest.json` - written alongside
`final.mp4`, since an upload manifest only makes sense paired with the
video it describes. Fields:

| Field | Description |
| --- | --- |
| `title` | `metadata.json`'s `topic`, truncated to YouTube's 100-char limit |
| `description` | Generated: topic line, calming intro, chapter timestamps, channel blurb, subscribe CTA |
| `tags` | Heuristic keyword list: topic segments plus fixed channel tags, capped under YouTube's 500-char total |
| `chapters` | `[{title, start_time_seconds, start_time_formatted}]`, first chapter forced to `0:00` |
| `category` | `{name, id}` - guessed from the topic (history/mythology keywords -> Education, else Entertainment) or `--category` |
| `playlist` | Derived from the topic's `| Theme` suffix, or `--playlist` |
| `privacy_status` | `unlisted` by default (safest before human review - reachable only via direct link, not published or searchable), or `--privacy` |
| `scheduled_publish_time` | `null` by default, or the ISO 8601 timestamp passed via `--publish-at` |
| `thumbnail_path` / `thumbnail_exists` | Path (relative to the repo root, e.g. `final/<slug>_<date>/thumbnail.png`) and whether it currently exists |
| `source` | `topic`, `final_video_path`, `subtitles_path` - traceability back to the inputs, also relative to the repo root |

All path fields are stored relative to the repository root, not as
absolute filesystem paths - `upload_manifest.json` describes upload
content, so it shouldn't embed this machine's local layout or username.

## How it works

1. **`manifest_reader.py`** - pure parsing, no AI. Reads `metadata.json`,
   `edit_manifest.json`, `production_manifest.json`, and locates the
   final assets.
2. **`metadata_builder.py`** - pure functions (no file I/O) that turn
   those inputs into every `upload_manifest.json` field, plus
   `validate_upload_manifest()`, which checks the result against
   YouTube's basic constraints (title/description/tag length, chapter
   count and spacing, thumbnail presence) and returns human-readable
   warnings.
3. **`providers/`** - `PublishProvider` is the interface every upload
   provider implements (`publish(upload_manifest, final_folder)`);
   `manual_provider.py` is the only one wired up today.
4. **`organizer.py`** - reads the inputs, calls `metadata_builder.py`,
   writes `upload_manifest.json`, and (for `publish`) loads it back and
   hands it to the selected provider.
5. **`main.py`** - CLI wrapper.

## Usage

```
python publishing_agent/main.py prepare --from-script scripts/<topic-slug>_<date>
python publishing_agent/main.py prepare --from-script scripts/<topic-slug>_<date> --force
python publishing_agent/main.py prepare --from-script scripts/<topic-slug>_<date> --privacy unlisted
python publishing_agent/main.py prepare --from-script scripts/<topic-slug>_<date> --publish-at 2026-08-10T18:00:00Z
python publishing_agent/main.py prepare --from-script scripts/<topic-slug>_<date> --playlist "Custom Playlist" --category "People & Blogs"

python publishing_agent/main.py publish --from-script scripts/<topic-slug>_<date>
python publishing_agent/main.py publish --from-script scripts/<topic-slug>_<date> --provider manual
```

- `prepare` builds `upload_manifest.json`. If it already exists, it's
  left alone and reported as skipped - pass `--force` to rebuild it
  anyway (matching the same idempotency convention as every other agent
  in this project).
- `--privacy` (`private`/`unlisted`/`public`, default `unlisted`),
  `--publish-at` (ISO 8601, default none), `--playlist`, and
  `--category` override the corresponding manifest fields.
- `publish` loads an existing `upload_manifest.json` (run `prepare`
  first) and hands it to a provider. `--provider` selects one by name
  (default: `PUBLISHING_PROVIDER` in `.env`, or `manual` if unset).

## The `ManualProvider`

Free, offline, no API key, and no actual upload. Running `publish` with
it:

1. Runs `validate_upload_manifest()` against the manifest.
2. Prints a numbered checklist (video path, title, where to find the
   description, tags, category, playlist, thumbnail, privacy, schedule)
   for uploading by hand through YouTube Studio.
3. Prints any warnings (e.g. missing thumbnail, chapters too close
   together).
4. Returns `{"provider": "manual", "status": "ready_for_manual_upload"
   or "needs_attention", "video_id": None, "warnings": [...]}`.

## Adding a publishing provider

`publishing_agent/providers/` is where a future YouTube Data API
integration lives. `providers/base.py` defines the interface:

```python
class PublishProvider(ABC):
    @abstractmethod
    def publish(self, upload_manifest, final_folder):
        """Act on upload_manifest.json's dict for the video in final_folder."""
```

To wire one up later:

1. Write `publishing_agent/providers/<name>_provider.py` implementing
   `PublishProvider`.
2. Add one line to `get_provider()` in `providers/__init__.py`.
3. Feed it `upload_manifest.json` straight out of `organizer.py` - no
   other file in this agent needs to change.

`.env.example` already reserves `YOUTUBE_API_KEY` for this.

## Setup

No system dependencies. Only pip package is `python-dotenv`, already
used project-wide for `.env`.

## Tested against

Ran against the existing Nightfall Atlas Ancient Egypt project
(`scripts/fall-asleep-to-the-entire-story-of-ancient-egypt-pyramids-pharaohs-and-gods-ancient-history_2026-08-01/`):

- `prepare` wrote `upload_manifest.json` into the matching `final/`
  folder with an 8-chapter list whose timestamps exactly match
  `edit_manifest.json`'s real rendered `start_time_seconds` (e.g.
  `3:33` for "Down the Silver River", `25:48` for "The Last Hour Before
  Dawn"), a 96-char title under the 100-char limit, 13 deduplicated
  tags, category `Education` (topic contains "Ancient History"),
  playlist `Nightfall Atlas — Ancient History`, and `privacy_status:
  "unlisted"` (the default). `thumbnail_path`, `source.final_video_path`,
  and `source.subtitles_path` were all recorded relative to the repo
  root (e.g. `final/<slug>_<date>/final.mp4`), not as absolute local
  paths.
- Re-ran `prepare` with no `--force`: correctly skipped instead of
  rewriting.
- Re-ran with `--force --privacy private --publish-at
  2026-08-10T18:00:00Z --playlist "Custom Playlist" --category "People
  & Blogs"`: all four overrides applied correctly.
- Ran `publish` with no thumbnail present: `ManualProvider` printed the
  checklist and correctly warned `thumbnail not found`, returning status
  `needs_attention`.
- Generated a real 1280x720 `thumbnail.png` with `ffmpeg` into the
  `final/` folder, re-ran `prepare --force`: `thumbnail_exists` flipped
  to `true`. Re-ran `publish`: no warnings, status
  `ready_for_manual_upload`. Removed the test thumbnail afterward and
  rebuilt the manifest so the repo reflects the project's real state
  (no thumbnail yet).
- Confirmed bad input is rejected clearly: an invalid `--publish-at`
  raises `ValueError: --publish-at must be an ISO 8601 timestamp`; an
  unconnected `--provider` name raises `NotImplementedError` listing
  available providers.

## Out of scope

No real upload provider is connected yet - `publish` only ever reaches
`ManualProvider` until a YouTube Data API provider is added. This agent
does not generate thumbnails (only records the expected path), does not
parse `subtitles.srt` content (only records its path), and does not
manage playlists or scheduling on YouTube itself - it only records what
a provider would need to do that later.
